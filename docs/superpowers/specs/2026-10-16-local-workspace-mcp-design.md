# Local Workspace MCP 第一版设计

日期：2026-10-16

状态：用户于 2026-10-16 通过“继续”确认，进入实施计划阶段；本文件描述拟实现行为，不代表功能已完成。

## 1. 目标与已经确认的需求

实现一个本地工作区管理 MCP，让不同 Agent 在同一个项目中保存和恢复任务状态、共享知识，并能接手续做。MCP 应承担工作区初始化、任务定位、状态校验、版本检查、上下文组装和历史查询，而不只是生成文档模板。

已确认的要求：

- 第一版使用 Java / Spring Boot 技术栈，Agent 主动调用工具保存和恢复状态。
- 采用多文档工作区；之前讨论的单任务单文档方案已取消。
- 任务数据默认放在使用者项目的 `LocalWorkspace/` 下，避免与原有文档混淆。
- 自动安装 Agent 入口指引，不要求用户手工复制内容。
- 保留项目已有的 `AGENTS.md`、`task.md` 等内容。
- 长会话不等于不断追加聊天原文；当前摘要与历史分开，恢复上下文有长度预算。
- MCP 本项目的开发目录是 `C:\individual-event\Local-Workspace`。

主要验收场景：Agent A 创建任务并保存进度、关键决策和下一步；关闭 A 后，Agent B 连接同一项目的 MCP，能查找未完成任务，加载最新状态，核对项目文件后继续执行。

需要用户评审的实现选择：单进程绑定一个项目根目录；Markdown 作为业务事实来源；STDIO 作为首个传输；下文的工具边界、并发控制和长度预算。

## 2. 技术选择与边界

- Java 17、Maven、Spring Boot 3.5.16、Spring AI 1.1.8。
- 使用 `spring-ai-starter-mcp-server` 的同步 STDIO 服务；不启动 HTTP 服务。
- Spring AI 用于 MCP 协议和工具注册，不配置模型供应商，不需要模型 API Key。
- Markdown 是任务、进度、交接、知识的事实来源；JSON 只存工作区标识、格式版本等控制信息。
- 不使用 SQLite、向量数据库、远程服务或后台模型总结。
- 摘要、决策提炼、语义理解由调用 MCP 的 Agent 完成；MCP 做确定性的校验、检索和读写。
- 第一版不导入 Codex 或其他软件的私有会话日志，不自动监听全部文件变动，不执行项目命令。
- 不承诺客户端一定调用工具。入口指引与工具描述帮助 Agent 使用工具，不能替代客户端的行为控制。

官方依据：

- [Spring Boot 3.5 系统要求](https://docs.spring.io/spring-boot/3.5/system-requirements.html)：3.5.16 支持 Java 17。
- [Spring AI 1.1.8 发布说明](https://spring.io/blog/2026/06/12/spring-ai-1-1-8-1-0-9-avaialble-now/)：1.1.8 属于 Boot 3.5 版本线。
- [Spring AI 1.1 MCP Server Starter](https://docs.spring.io/spring-ai/reference/1.1/api/mcp/mcp-server-boot-starter-docs.html)：提供 STDIO、同步工具和注解注册支持。

## 3. 运行配置与项目定位

启动服务时必须设置 `local-workspace.project-root`，指向已经存在的使用者项目目录。工具不接受任意绝对路径；一个服务进程只访问这个项目。

`local-workspace.directory-name` 默认 `LocalWorkspace`，只允许单个目录名，不能包含路径分隔符、`.`、`..` 或 Windows 保留设备名。不同 Agent 可以各启动一个 STDIO 进程，指向同一个项目，依靠文件锁协调访问。

服务源码目录与使用者工作区是两回事：本项目源码保存在开发目录；只有调用 `workspace_init` 时，才在配置的使用者项目里创建工作区。启动服务不会自行初始化任何项目。

首次安装客户端的 MCP 连接配置仍由用户或客户端完成。自动补充指引指初始化后自动维护项目规则文件，不代表 MCP 能给所有软件静默安装连接配置。

## 4. 生成的文档与控制文件

```text
使用者项目/
├── AGENTS.md                         # 根目录入口，原文保留
├── task.md                           # 若原本存在，完全不接管
└── LocalWorkspace/
    ├── workspace.json                # schemaVersion、workspaceId、创建时间
    ├── AGENT_GUIDE.md                 # 公共工作流程
    ├── knowledge/
    │   └── <knowledgeId>.md           # 按需创建的主题知识
    └── tasks/
        └── <taskId>/
            ├── task.md               # 目标、范围、约束、计划、验收标准
            ├── STATUS.md             # 状态、进度、阻塞、下一步
            ├── handoff.md            # 最新交接摘要
            └── archive/
                └── <checkpointId>/   # 按里程碑或交接保存的历史快照
                    ├── checkpoint.json
                    ├── task.md
                    ├── STATUS.md
                    └── handoff.md
```

初始化只生成公共指南和必要入口，不创建空知识文件或示例任务。每个任务固定三个当前文档，历史快照和知识按需产生。如果根目录入口原本不存在，初始化加第一个任务共新建五个 Markdown；如果入口已存在，则新建四个并补充原入口。归档不会减少磁盘上的历史总量，也不自动删除历史。

`workspace.json` 中的格式标识用于判断目录是否属于本 MCP。已有非空同名目录却没有有效标识时返回冲突，不自动接管；用户可以配置其他目录名。空目录可以初始化。

任务 ID、知识 ID、检查点 ID 由服务生成，只包含安全的 ASCII 字符，标题单独存储。所有文件采用 UTF-8，内容可人工查看并提交 Git。

## 5. 自动安装入口指引

`workspace_init` 的 `guidanceTarget` 支持 `agents`、`claude`、`both`、`none`，默认 `agents`。`agents` 默认使用根目录 `AGENTS.md`；若根目录存在 `AGENTS.override.md`，使用该入口，避免补充到被覆盖的文件。`claude` 使用根目录 `CLAUDE.md`；`both` 分别安装；`none` 只创建工作区，不修改入口。

这是文件适配，不扫描或改写用户家目录里的客户端配置。业务工具本身不依赖 Agent 品牌。

入口文件位置依据 [Codex 的 AGENTS.md 发现规则](https://learn.chatgpt.com/docs/agent-configuration/agents-md)和 [Claude Code 项目指令说明](https://code.claude.com/docs/en/memory)。实际客户端是否启用这些入口仍取决于其版本和设置。

入口中只维护以下区块：

```markdown
<!-- LocalWorkspace:begin -->
本项目的 Agent 工作区位于 LocalWorkspace/。
开始或继续工作时，通过工作区 MCP 检查初始化状态、查找任务并加载上下文。
相关任务有多个且无法确定归属时，向用户确认任务，不自行猜测。
阶段完成时保存状态；交接前保存关键决策、相关文件、验证结果和下一步。
公共流程见 LocalWorkspace/AGENT_GUIDE.md。
<!-- LocalWorkspace:end -->
```

实际区块使用配置后的目录名。不存在的入口文件创建；已有入口保留受管区块外的字节、UTF-8 BOM 和换行风格。重复初始化替换同一区块，不重复追加。出现残缺标记或多个同名区块时返回冲突，不改原文；不尝试自动判断和重写原有规则的语义。

自动编辑只支持 UTF-8（含 BOM）；无法按 UTF-8 解码的已有文件返回编码错误。业务规则包含在初始化结果及 `context_load` 结果中，使当前 Agent 也能立即获得，而不依赖当前会话重新发现磁盘入口。

生成公共指南后保留用户对指南的修改，重复初始化不无条件重置。向新 Agent 软件接入时，可以再次初始化相应入口，无需手工复制指引。对方仍须已连接 MCP，并具有项目访问权限。

## 6. 数据格式与修改语义

当前文档使用 YAML front matter 保存 `schemaVersion`、`documentType`、对象 ID、标题、创建和更新时间等元数据；`STATUS.md` 另外保存任务状态，知识保存标签和关联任务。正文使用清晰的 Markdown 章节。

- `task.md`：目标、范围、约束、实施计划、验收标准。
- `STATUS.md`：已完成、当前工作、阻塞、下一步、相关文件、验证结果。
- `handoff.md`：交接摘要、关键决策及原因、接手注意事项、相关文件、验证结果。
- 知识文档：标题、标签、关联任务和正文。

每个文档使用原始字节的 SHA-256 标识内容。任务的 `revision` 是按固定顺序组合 `task.md`、`STATUS.md`、`handoff.md` 的三个哈希后再次计算的 SHA-256；知识的 `revision` 是该知识文件的哈希。读取返回 `revision`，修改时必须提交 `expectedRevision`。因此人工修改任一当前任务文档，也会使持有旧任务上下文的写入被拒绝，而不只检查进程内版本号。

`task_update` 一次完整替换 `task` 或 `status` 中的一个文档，输入使用相应的结构化字段。未选中的文档保持原样，不提供跨三个文档的事务式更新承诺。调用 Agent 应先读取、合并仍有效的信息，再提交完整的新内容。

任务状态为 `ACTIVE`、`BLOCKED`、`COMPLETED`、`ARCHIVED`。新任务默认为 `ACTIVE`，由调用者提供明确的下一步；`ACTIVE` 和 `BLOCKED` 必须有下一步，`BLOCKED` 必须说明阻塞。完成和归档状态允许下一步为空。归档后不在默认任务列表展示，文档路径保持不变；通过状态更新可以重新激活。

创建任务会生成说明、初始状态和明确注明“尚无交接记录”的交接文档，不伪造已完成步骤或验证结果。MCP 保存的是 Agent 提交的验证说明，不声称自己运行过对应测试。

## 7. MCP 工具接口

所有工具使用同一响应结构：`ok`、`data` 或 `error`、`warnings`。失败还通过 MCP 的工具错误语义标识；错误中包含稳定的 `code`、可读说明和必要的恢复提示，不把异常栈输出给调用者。

| 工具 | 主要输入 | 行为与返回 |
| --- | --- | --- |
| `workspace_init` | `guidanceTarget`，默认 `agents` | 初始化或复用工作区，安装入口，返回工作区信息、实际变更路径、入口状态和使用流程。 |
| `workspace_status` | 无 | 返回配置目录、是否初始化、入口安装状态和预算，不扫描任意其他项目。 |
| `task_create` | 标题、目标、范围、约束、计划、验收标准、下一步、标签 | 创建唯一任务 ID 和三个文档，返回文档修订标识。 |
| `task_list` | 状态、查询词、`offset`、`limit` | 默认排除归档，按更新时间倒序返回任务摘要；默认 20 条，上限 100 条，不返回完整正文。 |
| `context_load` | `taskId`、文档选择、可选知识 ID、`maxChars` | 组装指南、指定任务的当前信息和显式选定的知识；返回修订标识、下一步所在文档、实际包含清单和总长度。 |
| `task_update` | `taskId`、`document`、完整新字段、`expectedRevision`、可选 `checkpoint` | 校验并更新任务说明或当前状态；需要里程碑快照时先保存旧状态。 |
| `handoff_save` | `taskId`、交接字段、`expectedRevision` | 保存旧任务文档快照，再替换最新交接；返回当前修订标识和检查点 ID。 |
| `history_read` | `taskId`、可选 `checkpointId`、文档选择、`maxChars`、`offset`、`limit` | 未指定检查点时列出历史摘要，默认 20 条、上限 100 条；指定时读取该检查点内选定文档。 |
| `knowledge_save` | 新建或已有知识 ID、标题、标签、关联任务、正文、已有文件的 `expectedRevision` | 新建或替换主题知识，不把一次任务的流水账自动提升为共享知识。 |
| `knowledge_search` | 查询词、标签、可选关联任务、`limit` | 返回知识 ID、标题、标签、正文短预览及修订标识；默认 10 条，上限 20 条。 |

任务标题和标签使用不区分大小写的文本匹配。知识检索使用标题、标签和正文的子串匹配，排序为标题命中优先、标签命中其次、正文命中再次，同分按更新时间倒序；指定多个标签时必须全部匹配。知识正文预览最多 200 字符，并标明是预览。不将其描述为语义检索。

`context_load` 和知识读取接受文档选择；默认包含指南、任务说明、状态和最新交接，不包含历史。知识搜索只返回预览，正文由 `context_load` 显式选择知识 ID 后读取。不设进程级“当前任务”，每次修改必须指定任务 ID，避免不同 Agent 的任务串线。

当前进度与下一步以 `STATUS.md` 为准，`handoff.md` 提供接手背景。如果交接更新时间早于状态更新时间，返回交接可能陈旧的提示，要求接手 Agent 先核对当前状态和项目。工具结果不把较旧交接中的下一步覆盖到当前状态。

## 8. 长度预算与历史管理

长度按 Unicode code point 计数，不把中文字符数当成模型 token 数。默认限制可通过配置调整：

- 当前任务文档、状态和交接：每个 8,192 字符。
- 公共指南：8,192 字符；知识正文：16,384 字符。
- 上下文及历史读取结果：默认预算 24,000 字符，调用者可选 4,000 至 64,000 字符。
- 单个输入文件实际字节另设 256 KiB 硬上限，先检查大小再读取；符号链接文件不读取。

预算覆盖返回的上下文文本和必要包装信息。核心文档合计超过预算时，返回 `BUDGET_EXCEEDED`、所需长度和可选择的文档，不无提示截断目标、约束或下一步。调用者可以提高预算或分文档读取。

写入超过文档限制时返回 `SUMMARY_REQUIRED`，保留现有文件；Agent 自己整理后重试。MCP 不在后台调用模型压缩内容。

`handoff_save` 和明确指定的里程碑更新才生成历史快照，普通进度小改不自动复制三个文档。快照包含当时三个文档及其哈希、时间和原因，默认永不加载到当前上下文，也不提供第一版自动清理功能。

## 9. 文件边界、锁与失败恢复

### 路径范围

所有工具路径从启动时配置的项目真实路径构建。任务、知识、检查点只能按服务生成的 ID 定位，拒绝 `..`、绝对路径、分隔符、设备名等非法 ID。资料中提到的源码路径只是文本，MCP 不跟随它读写源码。

工作区内部不跟随符号链接、junction 或其他 reparse point；根目录入口同样检查。允许写入工作区目录，此外只允许写入已选择的根目录入口文件。不能通过参数把工具变成通用文件系统。

### 并发与单文件替换

所有读取和修改在项目级锁内进行。JVM 内使用互斥锁，跨进程使用 `FileChannel` 文件锁；锁文件保存在系统临时目录的应用子目录，以项目真实路径的哈希定位，避免在项目根目录增加锁文件。等待上限 5 秒，超时返回 `WORKSPACE_BUSY`。

写入已有文档时，先检查 `expectedRevision`，准备同目录临时文件，刷新内容，再原子替换目标。文件系统不支持所需原子操作时返回错误，不降级成先删除旧文件再写入。一次工具修改一个当前文档，因此不依赖多文件原子替换。

项目锁协调遵守本 MCP 协议的进程。替换前再检查读取过的文件哈希以发现人工编辑；对不遵守锁的外部程序同时写入，不宣称提供操作系统级的比较并交换事务。

创建任务先在工作区内准备完整临时目录，再整体移动到唯一任务 ID。检查点也先准备完整目录再发布，失败时已有当前文档不受影响。启动或初始化时只清理能通过本应用命名及标识验证的未发布临时产物。

### 初始化失败

先发布带格式标识的工作区，再更新根目录入口。若入口更新失败，返回 `PARTIAL_INITIALIZATION`，明确工作区已创建、入口尚未安装；重试可补完，不清空已有任务。`workspace_status` 能显示这种状态。

已经存在的非空非本工具目录、损坏的元数据或入口标记都返回明确错误。检查点写入失败时不替换当前文档；检查点成功但当前文档替换失败时保留旧当前文档，错误说明已经生成的快照，避免误报保存成功。

主要错误码：`NOT_INITIALIZED`、`NOT_FOUND`、`INVALID_ARGUMENT`、`PATH_NOT_ALLOWED`、`WORKSPACE_CONFLICT`、`REVISION_CONFLICT`、`WORKSPACE_BUSY`、`FORMAT_ERROR`、`ENCODING_UNSUPPORTED`、`SUMMARY_REQUIRED`、`BUDGET_EXCEEDED`、`PARTIAL_INITIALIZATION`、`IO_ERROR`。

## 10. 组件职责

- MCP 工具层：暴露工具、生成参数说明、转换结果和错误，不直接拼接文件路径。
- 工作区服务：初始化、项目身份和入口安装状态。
- 任务服务：创建、列表、状态校验和任务上下文。
- 交接与历史服务：生成和读取完整检查点。
- 知识服务：主题存储、文本检索和关联任务校验。
- Markdown 编解码：元数据校验、结构化字段渲染、UTF-8 读写。
- 文件存储层：路径边界、跨进程锁、修订哈希、原子发布。
- 入口适配层：规则文件选择、受管区块更新、原文保护。

各组件通过 Java 接口或明确的服务方法协作，不在第一版拆成多个部署服务。

## 11. 使用流程与交付物

首次使用：配置 MCP 连接和项目根目录 → 调用 `workspace_init` → 返回接入指引 → 创建或查询任务 → 加载任务上下文。

工作中：Agent 修改实际项目 → 记录验证证据 → 使用最新修订标识保存状态 → 在阶段完成或切换前保存交接。

换 Agent：连接同一项目 → 查询未完成任务 → 明确任务 ID → 加载上下文 → 检查当前项目文件 → 继续。存在多个候选任务且用户意图不明时，由 Agent 询问，不由 MCP 选择一个全局“当前任务”。

如果上一个 Agent 未保存就中断，新 Agent 只能获得最后一次保存状态。指南应要求它核对代码和测试，不将陈旧记录当作最新事实。

交付可执行 JAR、中文 README、Windows 构建与启动示例、通用 STDIO JSON 连接示例和 Codex 连接配置示例。提供可复现的跨客户端演示。Spring banner 和日志不得污染 stdout；日志写 stderr，stdout 仅用于 MCP 协议。

## 12. 必须通过的验收

1. 空项目初始化成功，生成正确目录和入口；重复执行不重复追加，不抹掉用户编辑的公共指南。
2. 项目原有 `AGENTS.md`、根目录 `task.md` 内容受保护；UTF-8 BOM、CRLF、override 入口和损坏标记有覆盖用例。
3. 非本工具的同名工作区目录被拒绝；配置不同目录名后正常初始化。
4. 创建两个任务后，目标、状态、交接、历史和知识关联不会串线；默认任务列表排除归档。
